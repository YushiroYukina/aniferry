# 使用番舟

## 第一次启动

解压完整 Windows 压缩包，双击 `AniFerry-2.0.0.exe`。请保留同目录下的 `_internal` 文件夹。程序不会安装下载器，请自行安装并打开要使用的下载器。

在“设置 → 常规”选择实际下载目录。为兼容旧版本，未设置时的默认目录仍是 `E:\动画\202610\追番`；没有 E 盘的用户应先修改它。默认检查间隔为30分钟，可改为至少5分钟。

## 添加与查看动画

点击“添加追番”，输入名称，使用“查找并补全名称”选择正确的 Bangumi 条目，确认季度，再保存。可用“保存并继续添加”连续录入；已有动画可批量补全缺失的罗马音和英文名。译名源没有对应字段时保持空白，不编造名称。

选择左侧动画可查看封面、简介、评分、评分人数、排名、分布及放送信息，下面同时显示候选资源。网络不可达时保留已有缓存。右上角主题选择可即时切换六套配色。

## 检索与筛选

勾选“定时检查”且程序保持运行时，定时查询 Nyaa、AnimeGarden、蜜柑和動漫花園。Nyaa 分别按中文、日文、罗马音和英文检索；补充源结合可用译名或 Bangumi 作品ID补充。不是每个来源都支持四种名称。

同 infohash 跨源合并。每集优先推荐 ANI；没有 ANI 时按可获得的做种数最多显示3个候选。来源没有做种统计时显示“未知”。片名、季度和作品ID再核对能减少误匹配，但仍应人工检查标题。

“追踪设置”中的集数范围独立保存在每部动画上，结束留空表示不限。无法识别集数的资源列为“待核对”。合集不当作已识别的单集。

“工具 → 来源状态 → 详细诊断”区分来源访问失败、零结果、片名不符以及全部被集数范围排除。站点RSS通常只包含有限近期结果，不能保证找齐历史集数。

## 下载器设置

| 下载器 | 需要填写 | 接收与完成确认 |
| --- | --- | --- |
| BitComet | 程序路径及实际使用的 `Downloads.xml` | 只读任务XML，核对哈希、目录、整项大小和完成字段 |
| qBittorrent | 启用 Web UI，填写地址、用户名、密码；默认 `http://127.0.0.1:8080` | WebUI API 上传种子并读取任务与全部文件进度 |
| aria2 | 已运行并启用RPC的核心、RPC地址、`rpc-secret`；默认 `http://127.0.0.1:6800/jsonrpc` | `addTorrent` 提交，按GID/infoHash、目录及文件进度核对 |
| Motrix | 使用aria2核心的Motrix 1.x；RPC地址、授权密钥；默认 `http://127.0.0.1:16800/jsonrpc` | 使用其aria2 RPC；其他核心或不同版本未验证 |
| 迅雷 | `Thunder.exe` 和 `Profiles/TaskDb.dat` | 启动种子新建窗口，手动确认目录；只读任务库核对哈希、目录及整项完成 |

先点“测试连接”再保存。动画页面可切换默认下载器，历史任务保留原连接归属。需要 Windows 可访问的下载目录；Linux/NAS路径映射和跨系统下载器尚未验证。

确认资源后单选候选并点击“转交”。种子校验哈希后保存到应用数据目录的 `torrents/`，并在目标目录 `_种子/` 保留副本。提交后先显示“待接收”，只有匹配到任务哈希和目录才显示“已转交”。启动程序、接口返回成功都不等于已接收或已完成。

迅雷需要在新建任务窗口确认同一下载目录；若目录不同会提示而不确认接收。接口提交结果不明时保留待接收以避免重复；请在下载器核对后，在“转交历史”中重置再重试。

## 完成进度与旧集清理

### 分割季度与连续编号

对于标题包含“第2部分 / 第2クール / Part 2”等标记的条目，番舟会先读取其Bangumi正篇分集表。若表中确认采用连续编号（例如13～24），可用不带后缀的总标题搜索，只保留对应范围的正篇。明确标识该部分而从01重新编号的资源，会换算为全篇编号以便去重与完成追踪。集数筛选、候选表及完成记录使用全篇编号；例如本部分第3集对应全篇第15集时，筛选15可只看这一集。

已核对范围保存在本地 `search-cache/`，24小时内复用；刷新失败时可复用30天内已核对范围。首次分集资料不可用、不完整或无法确认连续编号时，保留完整名称检索并显示诊断，不猜测偏移量。“Season 2 / 第2季”不会被当作分割季度自动去掉。不同来源并行检索，临时网络错误最多重试一次；来源分页存在上限，不保证收录全部历史资源。

每15秒只读下载器状态。只有确认完整文件下载才更新最高已完成集数；只选下种子内部分文件不会自动认定整集完成。第 n 集完成后，弃置小于 n−1 的未转交候选，例如第5集完成后弃置1～3、保留4。

aria2建议配置会话保存和恢复。如果完成任务记录已被下载器清除、番舟未曾观察到完成，可在历史中人工确认已接收任务完成。程序关闭期间停止定时检索和监测。

## 批量整理

动画列表和资源表支持 Ctrl/Shift 多选与 Ctrl+A 全选。“删除动画”会先列出所选数量及名称、统一备份数据库，再删除追踪记录；保留视频、种子和下载器已有任务。“忽略所选”只忽略所选待确认资源。

“工具 → 清除当前待核对”只清理当前动画尚未转交的待核对项，包括隐藏的和此前忽略的项。保留哈希清理标记，下一次检索不会恢复这些相同资源；其他新资源仍会进入候选。转交和打开资源页面须单选。

## 字幕后续处理

字幕仅按标题标记“标题声明中文 / 无中文 / 未知”，不代表读取过媒体实际字幕轨道。“无中文”和“未知”的已接收/已完成资源进入 `ai-subtitle-queue.json`，包含作品、集数、哈希和目录，便于交给其他工作流。

番舟不内置AI字幕生成、翻译或播放器；交给下一流程前须确认文件完整并检查字幕轨道。

## 缓存、数据与升级

应用数据在 `%LOCALAPPDATA%\AnimeTracker`。新名称沿用此目录以兼容原“追番信箱”；更名不会搬走追番记录。主要文件为 `tracker.sqlite3`、`bangumi-cache/`、`torrents/` 和字幕队列。关闭所有版本后复制整个目录可备份；不要在公开Issue或仓库提交这个目录。

资料刷新规则：首次为所有动画补抓；以后每天首次打开更新当天尚未成功刷新的条目；同一天距上次成功更新至少5小时，再进入某部动画详情时单独刷新。日期按北京时间 UTC+8；不是后台每5小时全库重抓。封面链接未变时复用本地图片，手动刷新可重取。新条目自动入队，失败保留缓存并限频重试。

密码/RPC密钥由当前 Windows 用户的DPAPI加密保存；换Windows用户后需要重新输入。它们不随程序压缩包提供。使用新版本前关闭旧版本，避免两个实例同时检索和监测同一数据目录。


## 2.0.0 界面入口

- 主界面“检查所选”检查左侧当前所选动画，Ctrl/Shift可多选；“工具 → 检查全部”执行全库检查。定时检查继续按全库执行。已有检查未结束时不会启动重复任务。
- 推荐列表保持ANI优先或每集最多3项。“全部候选”展示推荐外的其他有效候选，仍执行作品、季度、集数、已转交、忽略及排除词规则。选中一项查看匹配和字幕标记依据，可单选转交或批量忽略。窗口始终操作打开时的动画，不随主窗口切换而改变。
- “追踪设置 → 集数与显示”设置范围。续作或分割放送可启用“本季/全篇双集数”，默认关闭；未识别为续作的条目，可先确认作品类型。已核对的分集范围仅预填前序集数，不自动启用双集数。
- 前序12集时，资源使用全篇编号15，或使用本季编号3，都可显示“3 / 总15”。请按资源实际编号选择“资源使用”，筛选范围可选本季或全篇，换算后沿用原来的下载与完成记录。关闭显示不会重写历史。
- “追踪设置 → 搜索偏好”按行填写补充名称及排除词。预览只检查本地候选；补充名称会参加后续检索。更改排除词不会删除历史、忽略或完成标记。
- “工具 → 来源状态”区分连接正常、部分可用、连接失败与尚未检查，成功但零结果不会被标为网络失败。最近成功时间跨扫描及重启保留；旧版无时间戳的记录不推测时间。详细查询、集数/偏好排除、重试和限速信息在“详细诊断”查看。
- “工具 → 使用说明”集中保存编号、缓存、来源限制及活动记录，主界面不常驻展示技术说明。“清除当前待核对”、转交历史、下载目录及字幕清单也位于工具菜单。

同一来源请求串行且保持最小间隔；连续失败后短暂退避，服务器返回等待时间时最多等待5分钟。其他来源仍能返回结果。候选按查询增量显示，但完成整轮后才保存整轮诊断。
